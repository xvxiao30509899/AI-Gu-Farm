# 游戏本运行手册（C 的机器 · 唯一有 GPU 的机器）

> 实测档案：RTX 5070 Laptop / 8151 MiB / 驱动 591.91 / Python 3.13.14 / git 2.55
> 关键约束：**C 盘只剩 31 GB**，所有模型和临时文件必须落 D 盘。

---

## 0 先接受一个修正结论

8 GB 显存跑不动全量实验，原因算给你看：

| 场景 | 调用次数 | 输出 token（按 300/次） | 60 tok/s 下耗时 |
|---|---|---|---|
| calibration（6 策略 × 20 题 × 3 次） | 360 | 108k | **0.5 h** ✅ |
| pilot 5 代 | 390 | 117k | **0.6 h** ✅ |
| 单趟正式运行（20 代） | 1560 | 468k | **2.2 h** ⚠️ |
| 全量 6 趟 + 留出评测 | 13563 | 4.07M | **19 h** ❌ |

**结论**：本地负责 pilot、calibration、断网演示兜底；**正式 6 趟走云端**。

云端成本粗算：13563 次 × (输入 800 + 输出 300) ≈ 10.9M 输入 + 4.1M 输出 token。按 DeepSeek 公开价（输入 ¥2/M、输出 ¥8/M）约 **¥55**；即便输出翻三倍也在两百元内。**预算不是卡口，速度才是。**

## 1 今晚五步，照着敲（Git Bash）

### 第 1 步 · 把模型目录钉到 D 盘（必须最先做）

```bash
setx OLLAMA_MODELS "D:\ollama\models"
setx OLLAMA_HOST "0.0.0.0:11434"
setx OLLAMA_NUM_PARALLEL 2
setx OLLAMA_KEEP_ALIVE -1
mkdir -p /d/ollama/models
```

- `setx` 写的是用户环境变量，**当前窗口不生效**，敲完关掉终端重开
- `OLLAMA_KEEP_ALIVE=-1` 让模型常驻显存，避免每次冷启动 20 秒
- 不设 `OLLAMA_MODELS` 的话权重默认落在 `C:\Users\ASUS\.ollama\models`，7B 约 4.7 GB，你 C 盘只剩 31 GB，别赌

### 第 2 步 · 装 Ollama

```bash
winget install --id Ollama.Ollama -e --accept-source-agreements
```

- 网慢就先下到 `D:\WorkBuddy-temp\installs` 再手动装
- 装完确认：`ollama --version`

### 第 3 步 · 拉模型（选 Q4 量化，8 GB 唯一稳的选择）

```bash
ollama pull qwen2.5:7b-instruct-q4_K_M
ollama list
```

- 4.7 GB 权重 + 4k 上下文 KV ≈ 6 GB，8 GB 显存刚好够
- **不要拉 14B**，会爆显存退化到内存跑，速度掉到 5 tok/s 以下
- 拉完先 `ollama run qwen2.5:7b-instruct-q4_K_M` 聊一句，确认能出字

### 第 4 步 · 自测「能不能返回合法 JSON」（这是唯一的硬验收）

```bash
curl -s http://localhost:11434/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"qwen2.5:7b-instruct-q4_K_M","messages":[{"role":"user","content":"输出一个 JSON 对象，含字段 a 和 b，a 为整数 1，b 为字符串 ok。只输出 JSON。"}],"temperature":0}' | head -c 400
```

**验收**：返回体里 `choices[0].message.content` 能被 `json.loads` 解析。解析不了就加 `"format":"json"`，还不行就换 `qwen2.5:7b-instruct` 的非量化版本试一次。

> 出题 prompt 要求结构化输出，模型连 JSON 都给不稳，后面 78 次调用会全是格式失败——这一步不过，今晚别往下走。

### 第 5 步 · 让 B 的办公本能连上（局域网共享）

```bash
ipconfig | grep -A 4 "无线局域网适配器 WLAN" | grep "IPv4"
```

拿到形如 `192.168.1.23` 的地址后，**用管理员 PowerShell** 放行端口：

```powershell
netsh advfirewall firewall add rule name="Ollama-11434" dir=in action=allow protocol=TCP localport=11434
```

B 那边调 `http://192.168.1.23:11434/v1/chat/completions` 即可，模型 id 填 `qwen2.5:7b-instruct-q4_K_M`。

**注意**：`0.0.0.0` 绑定意味着同一 WiFi 下任何人都能调你的模型，比赛现场没关系，回宿舍记得改回 `127.0.0.1`。

## 2 电源与散热设置（不设就会在半夜掉链子）

```bash
powercfg /change standby-timeout-ac 0
powercfg /change hibernate-timeout-ac 0
powercfg /change monitor-timeout-ac 15
powercfg /change disk-timeout-ac 0
powercfg /setactive SCHEME_MIN
```

`SCHEME_MIN` 就是「高性能」。再手动确认三件事：

1. 机身电源管理软件里开**独显直连 / 狂暴模式**（联想 Legion Space、华硕 Armoury Crate 之类）
2. 合盖不休眠：控制面板 → 电源选项 → 选择合上盖子的作用 → 插电时「不采取任何操作」
3. 垫高机身或上散热架，8 GB 卡跑满 8 小时会明显降频

## 3 Git 工作流（仓库已建好，本地还没 clone）

### 第 1 步 · 先配身份（你现在是空的，不配 commit 会失败）

```bash
git config --global user.name "xvxiao30509899"
git config --global user.email "你的GitHub邮箱"
git config --global core.autocrlf false
```

`autocrlf false` 很重要：三人跨机器，行尾转换会让 diff 全是噪音。

### 第 2 步 · clone 到 D 盘（别放 C 盘）

```bash
cd /d/WorkBuddy-temp
git clone https://github.com/xvxiao30509899/<仓库名>.git
```

### 第 3 步 · 先写 `.gitignore`（第一个 commit 就包含它）

```gitignore
__pycache__/
*.pyc
.venv/
.env
.pytest_cache/

logs/
runs/
snapshots/
models/
*.snap
*.log

web/history.json
```

**三条禁令**：模型权重不进仓库、日志不进仓库、`.env` 和 API key 永不进仓库（GitHub 单文件 100 MB 上限，超了直接推不上去）。

### 第 4 步 · 分支策略（三人四十二小时，别搞复杂）

| 做法 | 理由 |
|---|---|
| 直接推 `main`，推前 `git pull --rebase` | 文件完全不重叠（A 判分 / B 引擎 / C 管道），冲突概率极低，走 PR 会浪费半小时 |
| commit message 前缀带角色 | `[C] datasets: 四类题集签名互斥`，回溯时一眼看出谁改的 |
| **禁止 `push --force`** | 会把别人的活冲掉 |
| 12H、22H 各打一个 tag | `git tag lock-22h && git push --tags`，锁协议那一刻的代码状态必须可追溯 |

### 第 5 步 · 每天两次同步节点

- **开工前**：`git pull --rebase`
- **12H / 22H 对齐点之后**：`git add -A && git commit -m "[C] xxx" && git pull --rebase && git push`

## 4 分给 B 用的两条接口约定

B 的 `llm.py` 要同时支持本地和云端，你这边只要保证三件事：

1. **端口固定 11434**，路径 `/v1/chat/completions`（OpenAI 兼容）
2. **模型 id 稳定**，不要随手 `ollama rm` 再拉别的版本——id 变了 B 的 config 就得改
3. **服务常开**，B 开发到一半你重启服务，他的请求会 500

启动方式（开机自启更省事）：

```bash
ollama serve
```

## 5 22–30H 正式运行期间，这台机器该干什么

正式跑走云端，**你的 GPU 这时候是空闲的**，正好干三件事：

| 干什么 | 注意 |
|---|---|
| OBS 录 90 秒素材 | 用 NVENC 硬件编码，不吃 CPU；但别同时开本地推理 |
| `export.py` 出展板图 | 纯 CPU 活，随便跑 |
| **不要**开着本地模型服务 | 显存被占会拖慢 OBS，画面掉帧 |

## 7 现场演示机（这台机器还有一个身份）

因为这是全场唯一有 GPU 的机器，**它同时是现场演示机**：舞台上那段"现场跑 1–3 代"必须在这台上跑。所以 36H 之后要把它当一个交付物打包，而不是一台随便用的笔记本。

### 打包清单（36H 前完成）

- [ ] 充电器 + 排插 + Type-C 备用供电（展位不一定有插座）
- [ ] 散热垫
- [ ] 演示模式脚本 `demo.bat`（双击即进状态）
- [ ] 录屏文件本地存一份 + U 盘再存一份
- [ ] `web/` 静态页能双击打开（断网验证）
- [ ] 关闭所有开机自启软件（微信、更新助手、云盘同步）

### `demo.bat`（放在仓库根目录，双击运行）

```bat
@echo off
chcp 65001 >nul
set OLLAMA_MODELS=D:\ollama\models
set OLLAMA_HOST=127.0.0.1:11434
set OLLAMA_KEEP_ALIVE=-1
echo [1/3] 启动本地模型服务...
start "" /min ollama serve
timeout /t 8 >nul
echo [2/3] 预热模型...
ollama run qwen2.5:7b-instruct-q4_K_M "回复 ok" >nul 2>&1
echo [3/3] 打开大屏...
start "" "web\index.html"
echo 演示环境就绪。断网也能跑。
pause
```

### 演示前的三分钟检查

1. **拔掉网线再试一次**——最丢人的事故是"现场网络不稳，演示打不开"
2. 关闭 Windows 通知（专注助手 → 仅闹钟），弹窗会毁掉录屏
3. `nvidia-smi` 看一眼显存：模型未加载就点 `demo.bat` 预热，别在台上等 20 秒

## 8 三条现场禁令

1. **正式运行窗口内不许装显卡驱动、不许让 Windows 自动更新**（重启会毁掉一趟运行）。跑之前手动暂停更新 35 天
2. **不许再往 C 盘装东西**，只剩 31 GB，Windows 更新一次就可能撑爆
3. **不许把 `logs/` 和模型权重推 GitHub**，一次推送失败能折腾半小时
